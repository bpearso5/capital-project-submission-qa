# Pre-Submission Checklist

Completed by the submitter before routing. The analyst confirms it before the submission moves forward. All eight must pass.

| # | Check | How to verify | Prevents |
|---|---|---|---|
| 1 | Cost code matches an approved budget line | Compare to the current budget line list for the project | R1 |
| 2 | Amount is within the remaining commitment balance | Remaining = commitment − invoiced to date | R2 |
| 3 | PO number present and matches the commitment | Match the PO on the document to the commitment record | R3 |
| 4 | Signed pay application attached | Contractor and architect signatures present | R4 |
| 5 | Conditional lien waiver attached for this period | Period and amount match the pay application | R4 |
| 6 | Approver matches the routing matrix for this amount and region | Check the threshold tier before routing | R5 |
| 7 | Retainage calculated at the contract rate | Recalculate; line totals tie to the summary | R6 |
| 8 | Document type and project ID are correct | Matches the project record exactly | R1 |

## Why it's built this way

Each item exists because a specific rejection kept recurring. If a check doesn't map to a real failure, it doesn't belong on the list, because long checklists get skimmed.

Two failure types (R2, R5) can't be fully stopped at submission. Budget balances and approver assignments change upstream, so those need a process fix as well: a scheduled budget-line refresh and a published routing matrix.
